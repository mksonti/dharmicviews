## Notes on methodology corrections made during this audit

An initial pass used naive substring matching for risky-content keywords (e.g. "xxx", "cialis"), which produced false positives from unrelated word fragments (e.g. "spe**cialis**t", UUID template strings like `xxxx-xxxx-4xxx`). All findings in the **HIGH — gambling/adult** section above were re-derived using word-boundary regex matching and independently re-verified with a second live fetch before being included. Eight domains that showed a gambling-keyword hit on the first pass did not reproduce it on the second pass; these are listed separately in **LOW — unconfirmed** rather than being asserted as compromised, since intermittent/rotating ad injection on parked domains is a known pattern that can produce this exact behavior.
